# PC-Cast

> 用纯 Go 写的跨平台 DLNA / UPnP 投屏接收端 —— 把你的电脑变成手机可以投屏的「电视」。

PC-Cast 在本机实现一个标准 `MediaRenderer:1` 设备：启动后只弹一条桌面通知，随后常驻系统托盘。手机与电脑处于同一局域网时，视频 App 可在投屏列表里发现本设备并推送视频/音频/图片。**Windows 版内置 mpv 播放器，开箱即用**；也可在设置中切换为本机安装的播放器。程序自身不解码、不转码、不中转媒体流。

当前版本：`v0.6.0` ｜ 语言：Go 1.27.4

## 功能特性

- **零依赖部署**：单个可执行文件，Windows 构建为 GUI 子系统，双击不弹控制台。
- **完整投屏链路**：手机可发现设备、推送视频/音频/图片，支持播放、暂停、跳转、音量等控制。
- **兼容国内视频 App**：针对固定端口、直播流与常见投屏 SDK 行为做了适配。
- **内置播放器**：Windows 版随程序内置 mpv，首次启动自动解压到缓存目录，无需另行安装；默认优先使用，可在设置中切换。
- **播放器自动适配**：内置不可用时按环境探测本机播放器并分级降级，不再回退到「系统默认程序」；找不到播放器时设备仍可被发现。
- **即改即用的设置**：托盘设置页保存即生效；托盘、通知与关于窗口图标在深浅主题下通用。

## 快速开始

### 1. 环境要求

| 项 | 要求 |
| --- | --- |
| Go | 1.27.4 及以上（仅构建时需要；运行只需二进制） |
| 操作系统 | Windows / macOS / Linux（详见[平台支持与已知限制](#平台支持与已知限制)） |
| 播放器 | Windows 内置 mpv（开箱即用）；macOS / Linux 需本机安装 mpv 或 VLC 3.x |
| 网络 | 手机与电脑同网段，允许 UDP 1900 组播与 TCP 8768 入站 |

### 2. 构建

```bash
# 标准方式（产出 bin/pc-cast.exe）
make build

# 无 make 环境的等价命令（Windows GUI 版）
go build -trimpath -ldflags "-s -w -H=windowsgui -X pc-cast/app.Version=0.6.0" -o bin/pc-cast.exe .

# Linux / macOS（不要带 -H=windowsgui）
go build -trimpath -o bin/pc-cast .
```

Windows 可执行文件会自动带上图标，无需额外参数；打包与图标的定制方法见 [构建与打包](doc/build.md)。

### 3. 运行

双击 `bin/pc-cast.exe`（或执行 `bin/pc-cast` / `go run .`）。程序没有主窗口，只会：

1. 弹出一条「PC-Cast 已启动」桌面通知，其中含服务地址与当前播放器名称（完整控制后端只显示名字，弱后端会附能力标签提示）；
2. 在系统托盘出现图标，右键即可打开菜单。

首次运行请确认：

- 防火墙放通 **UDP 1900 入站**（SSDP 发现）与 **TCP 8768 入站**（设备描述 / SOAP / 事件）；若 8768 被占用，程序会依次尝试 8769…8779，实际端口看启动通知或日志。
- Windows 网络位置设为「专用网络」；公用网络配置下组播常被拦截。
- 托盘菜单里「启用投屏」处于勾选状态。

随后在手机视频 App 中选择投屏设备 `PC-Cast (<主机名>)` 即可。若手机此前连过旧端口，需**强制停止并重启 App** 刷新设备缓存。

## 使用说明

### 托盘菜单

| 菜单项 | 作用 |
| --- | --- |
| 状态：… | 只读状态，2 秒刷新（空闲 · 等待投屏 / 投屏中 / 投屏已关闭） |
| 复制当前播放地址 | 复制最近一次投屏的媒体 URL |
| 设置… | 打开设置窗口，调整设备名、端口、播放器、窗口等 |
| 启用投屏 | 总开关；关闭后手机无法发现设备 |
| 全屏播放 | 勾选后播放窗口尺寸设置不再生效（全屏优先） |
| 收到投屏自动播放 | 关闭后需手机端主动发播放指令 |
| 开机自动启动 | 调用系统 API 设置自启 |
| 软件信息 | 版本、构建、服务地址、UUID、当前播放器与能力等 |
| 打开配置目录 | 打开配置文件所在目录 |
| 退出 | 完整停止服务与播放器后退出 |

### 托盘图标状态

托盘图标、启动通知与软件信息里的状态徽标共用同一套状态判定：

| 图标 | 状态文案 | 含义 |
| --- | --- | --- |
| 绿色角标 | 投屏中 | 正在播放 |
| 琥珀角标 | 空闲 · 等待投屏 | 未在播放——包括内置 mpv 待机；弱后端会额外标注「能力受限」 |
| 灰阶角标 | 投屏已关闭 | 托盘菜单里关闭了「启用投屏」 |

### 配置文件

设置页调整后即写入配置，也支持手工编辑。配置与日志位置：

| 平台 | 路径 |
| --- | --- |
| Windows | `%AppData%\pc-cast\config.json`，日志同目录 `pc-cast.log` |
| macOS | `~/Library/Application Support/pc-cast/` |
| Linux | `$XDG_CONFIG_HOME/pc-cast/`（默认 `~/.config/pc-cast/`） |

全部配置字段与日志格式见 [配置与日志](doc/configuration.md)。

## 平台支持与已知限制

| 平台 | 状态 |
| --- | --- |
| Windows amd64 / arm64 | 实机验收；GUI 子系统、主题自适应托盘均可用 |
| Linux amd64 | 交叉编译通过；托盘需 `libayatana-appindicator3`（或兼容实现） |
| macOS arm64 | 交叉编译通过；未打包成 `.app` 时系统通知会降级为日志 |

其他限制：

- **DLNA 本身没有鉴权**，任何同网段设备都能向本机的 HTTP 端口下发播放指令。请在可信局域网使用，不要在公共 Wi-Fi 下开启。
- 内置 mpv 与本机 mpv / VLC 提供完整控制（真实进度、暂停、跳转、音量）；少数基础后端只能模拟部分控制，体验较弱。不再使用「系统默认程序」兜底。
- `window_size` 只控制窗口，不改变片源码率；`fullscreen` 与 `window_size` 互斥，全屏优先。
- 部分视频 App 的私有投屏协议与直播投屏策略未经端到端验证。
